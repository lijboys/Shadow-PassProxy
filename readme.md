1. 301 重定向 (永久搬家)
表面现象： 地址栏会变。你访问 A 域名，瞬间跳成 B 域名。

背后逻辑： 相当于你在旧房门上贴了个条：“我永久搬到B小区了，以后有事去那找我”。

特点： 浏览器和搜索引擎（比如百度、谷歌）看到 301 返回码后，会把旧网址的记录全部更新为新网址。浏览器甚至会把这个跳转“死死记住”（缓存），下次用户再输旧网址，浏览器都不去问旧服务器了，自己直接跳到新网址。

2. 302 重定向 (临时出差)
表面现象： 地址栏也会变。你访问 A 域名，同样跳成 B 域名。

背后逻辑： 相当于你在门上贴条：“我临时去B小区住几天，过阵子还回来”。

特点： 浏览器每次还是会先来敲旧房子的门问一嘴，确认你今天是不是还在 B 小区。搜索引擎也会保留旧网址的排名，不会把它替换掉。这也是为什么我在最开始给你写的那个跳转代码里用了 302，因为你可能会经常修改后台那个 url 变量，用 302 可以保证每次修改都能立刻生效，不会被浏览器缓存坑了。

3. 反向代理 / 反代 (专业代购)
表面现象： 地址栏绝对不会变！你访问 A 域名，看到的是 B 网站的内容，但地址栏死死钉在 A 域名上。

背后逻辑： 相当于你开了个跑腿公司（这就是你刚才部署的 Worker）。用户向你的 Worker 点单，你的 Worker 默默跑去目标网站把网页数据“买”回来，然后再原封不动地递给用户。

特点： 用户从头到尾都在和你的域名打交道，根本不知道背后那个真实网站（目标域名）的存在。这就是你现在真正想做的效果！
